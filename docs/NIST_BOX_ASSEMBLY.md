**Reduction rule.** Per log: take Program_Runtime_Seconds in file order; drop leading stale samples (a leading sample larger than its successor is the previous program's counter); the run time is the maximum of the remaining samples (the controller shows a single 0 at the 60 s mark and continues, and the counter pauses during feed holds, so the maximum is the program's running time); a log is usable only with a PROGRAM_COMPLETED status, at least one sample after the stale prefix and a wall-clock ACTIVE-to-PROGRAM_COMPLETED span >= run time - 5 s. Per (part, operation, machine): min / median / max / mean of the usable run times; the median is what the app uses. Nothing is filled in for an unusable or missing instance.

## Honest limits

- Only the machining programs are timed. Assembly, inspection, set-up, tool changes between programs, transport and demand are NOT in the dataset; where the app needs them they are labelled teaching values.
- The run time is the controller's program running time (feed holds excluded), not a cycle time with load / unload; the wall-clock span is reported only as a cross-check.
- A group with fewer files than the 20 instances (e.g. Box OP4) is reported as it is; nothing is filled in.
- The machine models are as documented by NIST; this is not a vendor specification or an endorsement.
