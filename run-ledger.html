A layered Sankey over the recorded links: one link per unit that moved from one operation to the next, so returns split into restock and scrap and cross-dock bypasses storage. What a handling unit costs

The spans between a unit's events, charged at the rates the run was recorded under (the planner's Analyze panel, defaults from analytics.js): a unit served at a station is charged that station's service time, whatever it waited; a moving unit is charged at the class of mover the floor contains. Cost per span = hours × labour rate (manned classes) + hours × capex ÷ amortisation years ÷ operating hours per year + hours × kW × energy price. Queue time costs no labour; a holding cost per unit-hour waiting is charged only if you set one in the planner's Analyze panel (default 0). Cost per order type is given per unit, per received each (every unit, retired or not) and per delivered each (partial while units are in flight).

Dispatch manifest

Packaging

The packaging hierarchy

Each → case → layer → pallet → trailer, from the scenario's packaging profile. The pallet pattern is the ti-hi the optimiser computes: cases per layer in the best layer, layers under the stack-height limit, reduced until the pallet's load limit and the board's strength hold.

Optimise the pallet pattern

Every candidate pallet for this profile's case, ranked by cases per pallet: the single-orientation grid, a band layout when strips of mixed orientation pack more (the one-dimensional knapsack of Smith & De Cani, 1980), or a four-block pinwheel when it packs more than both. Then the what-if on this run's own volumes: how many inbound pallets and trailers the same eaches would need. Partial dispatch pallets do not change; racking, handling and stability for a different pallet type are not modelled.

Your case

A case of your own on the EUR, industrial and half pallets and on a custom pallet: the best layer (grid, bands or pinwheel), the layers under the height, load and strength limits, and the verdict for the bottom case - the simplified McKee formula (BCT = 5.874 × ECT × √(caliper × perimeter)) with the published derating factors for humidity, time under load, overhang and stacking pattern. Prefilled from this run's profile. Informed by packaging practice, not a certification: a real load plan needs the board supplier's data.

Trace one unit

Tracking: the run in the EPCIS vocabulary

Every handling event on this page has one EPCIS-shaped twin - GS1 EPCIS 2.0 / CBV 2.0 identifiers used as vocabulary, no conformance claimed: a simulation has no wall clock - derived from this file by tracking.js and, at import, by the same mapping in tools/run_ledger.py (v3.53). Per business step: events and units, how long a unit stays at the step until its next event, and how much of that is waiting at a bench; then which steps produce which dispositions. A unit's own history sits beside its events under Trace one unit. Events are keyed to a handling unit, an element and a business step - never to a person.

Compare two runs

The same tables for two recorded runs, paired key by key: order type, bench and operation. Deltas are B − A. The same six comparisons are SQL views over every ordered pair of runs in one database.

Replications over seeds

Runs that share the floor, the order mix, the tick count and the staffing policy but differ in seed: per order type the mean, the sample standard deviation and a Student-t 95 % half-width over the seeds - the same four views SQLite computes over every run in one database.

The invariants

Each of these views must return zero rows. They are the same views the SQLite tool exposes; a deliberate corruption in the test suite makes every one of them fire.

Appendix: how to read this page

Deterministic: the same scenario, seed and order mix reproduce this file byte for byte. The viewer computes every table in the browser once, by the definitions shown under SQL; python tools/run_ledger.py import <file> --database run.sqlite then views runs them in SQLite. Unit-load dimensions follow DIN EN 13698 and VDA 4500; the 33 / 26 pallets per 13.6 m trailer are planning figures; everything about the goods themselves is a synthetic teaching value.
